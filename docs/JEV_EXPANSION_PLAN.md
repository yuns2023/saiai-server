# Jev 审核统一与扩展计划

状态：开发规划。第一阶段基于 PR #63；本文件不表示新增分类已实现、已验证或已上线。
目标：以 Jev 为唯一运行时审核引擎，明确检测范围与处罚范围，完成验证后退役 Qwen。

## 二、分类草案

借鉴原版 Sub2API 的细分方式，而非把它的模型分数视为已校准概率。
原版源码基线：`Wei-Shaw/sub2api@b0a02a3304a0a78cdd003ddda1dd23ba02c03084`。
参考 `backend/internal/service/content_moderation_typesafe.go`、
`content_moderation.go` 和 `content_moderation_engines.go`。

| 分类族 | 拟检测范围 | 排除或区别处理 |
| --- | --- | --- |
| 越狱 | 要求绕过高优先级指令、安全规则、泄露隐藏指令 | 正常改需求、引用分析、合法防御样本 |
| 隐私 | 未经授权获取、披露、交易或滥用个人数据和凭据 | 自有数据、授权处理、脱敏、受害者求助 |
| 非暴力违法 | 欺诈、盗窃、未授权入侵等具体协助 | 授权研究、恢复、举报、防御 |
| 骚扰/仇恨 | 定向骚扰、身份仇恨；可信暴力威胁独立细分 | 正常批评、报道、反对骚扰的引用 |
| 有害欺骗 | 明确恶意欺骗、诽谤等，补充非违法但有害行为 | 保留旧 Unethical Acts 的可解释映射，避免重复计次 |
| 暴力 | 暴力实施指导、威胁、血腥暴力细分 | 新闻历史、常规医学、安全防范；内容描写与实施意图分开 |
| 色情 | 成人露骨内容、未成年人性化、非自愿性剥削分别定义 | 非露骨恋爱、性教育、临床医学、受害者求助 |
| 自伤 | 自伤意图、鼓励、具体方法分别检测 | 意图/求助不作为自动处罚依据；预防与康复内容不应误判 |
| 政治相关风险 | 先记录具有明确行为定义的政治场景：定向威胁、煽动暴力、冒充或欺骗操纵；规则中说明与其他类别的重叠 | 不以人物姓名、立场或一般政治讨论作为违规条件；若需要更广的平台内容限制，必须另行明确范围，不能宣称本规则覆盖所有“政治敏感” |
| 版权风险 | 明确索取或分发受保护作品的大段内容、盗版访问协助等 | 摘要评论、短引用、公有领域、自有或授权内容；模型无法核实权利时保留不确定性，默认仅审计，不作法律裁定 |

类别最终数量在规则评审后冻结，不机械沿用旧九分类，也不以“18 类”之类的数量作为验收目标。
旧四分类的 key 与历史标签不能直接重命名覆盖。新增 canonical ID、中文名称、
规则版本与 legacy 映射；旧分组保持既有语义，新规则命中不能悄悄扩大其处罚集合。

## 三、策略和接口

- 全局配置负责 Jev 服务、固定模型版本和规则版本；分组负责检测集合、处罚集合和动作。
- 新策略明确 `audit_categories` 与 `enforcement_categories`，处罚集合必须是检测集合的子集。
- 分类注册表作为后端与前端共同来源。UI 展示“支持/未接入/仅记录”，拒绝保存未知类别。
- 新增分类默认检测但仅审计；引入现有分组时需显式启用扩展规则版本，不静默扩展已授权的检测范围。
- 自伤意图、一般政治话题与不确定版权判断不默认进入处罚集合。
- 支持分类阈值；已有统一 90% 阈值作为兼容回退，不复制原版不同模型的默认阈值。
- 记录决策时的模型/规则版本、阈值及处罚策略快照，避免随后改设置改变历史解释。
- 一条输入多个分类命中只计一次；跨分类/重试不能增加计次。审核失败不算通过、不计处罚。
- 保留冷却、告警、停用和管理员复核/恢复；永久停用不能成为所有新增分类的默认动作。
- 为结果元数据制定按时间/用量的清理规则，并验证清理不影响计费记录；不保留原始用户文本。
- 扩展分类所需数据库迁移编号以当时 canonical main 为准；不得改写已应用的迁移。

## 四、评测方案与准入

已有 40 条对照和 80 条校准只支持旧四分类的探索性结论；700 条草稿未运行、未独立复核。
不能复用校准集作为独立验收，也不能把同场景的改写变体当成独立样本。

1. 每类准备风险、正常及边界场景；中文/英文、引用/求助/防御、混合类别、提示注入均覆盖。
2. 按场景家族划分校准集与留出集。标签独立复核，标明多标签、争议及不确定案例。
3. 先做离线数据和模拟响应检查；冻结模型、规则、阈值、样本与工具哈希。
4. 付费评测前给出准确调用数、输入规模、费用估算、数据用途和重试上限，取得该次调用授权。
5. 报告每类 TP/TN/FP/FN、精确率、召回率、误报率及区间；同时报告总体风险命中，不能用总体命中掩盖类别漏标。
6. 自动处罚候选的初始目标为每类精确率 ≥99%、召回率 ≥95%；这只是待验收目标，不是现有能力声明。
   正常求助、恢复、防御、教育等保护场景出现误罚必须复核并阻止该类自动处罚。
   样本量不足以支撑目标时继续仅审计，不用小样本“零误报”宣称已满足真实流量指标。
7. 同时验证超时、限流、错误响应、拒绝/缺失分数、队列积压和恢复；不把失败样本排除后宣称满分。
8. 留出集失败后回到校准阶段，下一轮使用新的独立留出集；不得在同一留出集调参后仍称独立验收。
