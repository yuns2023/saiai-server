# 维护模式

管理员可在“系统设置 → 站点设置”中开启维护模式并填写提示文案。

开启后：

- 浏览器端读取公开设置后显示维护页面和自定义文案；
- `/api/`、`/v1/`、`/v1beta/`、`/sora/`、`/antigravity/` 和 `/responses` 下的新业务请求返回 HTTP 503；
- 503 响应的 `reason` 为 `MAINTENANCE`，并带有 `Retry-After: 60`；
- `/health`、公开设置接口和管理员设置接口保持可用，便于健康检查、展示文案和关闭维护模式。

建议升级流程：

1. 先开启维护模式并保存文案；
2. 等待已经开始的流式请求自然结束，再执行服务升级；
3. 启动新版本后确认 `/health` 正常；
4. 关闭维护模式并确认 API 恢复。

维护状态保存在数据库中，并在进程内短暂缓存。多实例部署应确保实例共享同一个数据库。应用完全停止后，Caddy 的错误页仍可能显示通用 502/503；如果需要在停机期间继续显示自定义维护页，还应在 Caddy/Cloudflare 层配置独立的维护响应。
