# 全局模型倍率与分组覆盖调整方案

状态：已取消。用户于 2026-10-17 明确取消本需求；不再实施或部署。以下仅保留历史设计，不属于待办或当前产品合同。
交互草图：[全局配置与分组覆盖](ui.html)。

## 目标与计费规则

在模型价格管理页保存全局模型倍率，分组可以覆盖。按量与订阅使用同一解析规则：

1. 分组精确模型规则。
2. 分组最长前缀规则（保留现有末尾 `*` 支持）。
3. 全局精确模型倍率。
4. 默认 `1`。

这些来源选出一个最终模型倍率，彼此不叠乘。`0` 是免费，`1` 是明确覆盖；删除规则才会向下一层查找。
删除分组精确规则后，如果仍命中分组前缀规则，应使用该前缀规则，而不是直接继承全局。
全局规则以实际计费模型 ID 为键，不沿价格映射继承另一模型的倍率。

| 全局倍率 | 分组规则 | 最终模型倍率 | 来源 |
| --- | --- | --- | --- |
| 未配置 | 未命中 | 1 | 默认 |
| 1.55 | 未命中 | 1.55 | 全局 |
| 1.55 | 精确值 2 | 2 | 分组精确规则 |
| 1.55 | 精确值 1 | 1 | 分组精确规则 |
| 1.55 | 精确值 0 | 0 | 分组精确规则，免费 |
| 1.55 | 仅命中前缀值 1.2 | 1.2 | 分组前缀规则 |

基础计费仍由单价、服务档位和上下文规则决定；最终模型倍率在既有用户收费阶段应用一次，
继续与有效分组整体倍率及用户折扣相乘。订阅窗口、钱包和 Key 金额限制使用最终用户金额。
上游账号成本继续保持现有基础金额口径，历史账单不重算。

## UI 调整

### 模型价格管理页

- 列表新增「全局倍率」列，显示 `1.55×`、`1× · 默认` 或 `0× · 免费`。
  单价列继续展示每百万 Token 的基础单价，不将倍率混进单价后再次乘算。
- 编辑弹窗把「全局模型倍率」放进正式配置区，与模型映射、单价同属于可保存设置。
  输入范围 `0–100`，最多四位小数；留空显示「1（默认）」。短提示：
  「分组未设置模型倍率时使用；分组配置优先。」
- 打开弹窗读取已保存值；切换模型重新初始化草稿。保存成功后重新读取服务端配置，
  列表、再次打开编辑和刷新页面均显示保存结果。
- 有有效配置改动即可保存，不要求先试算。无改动、输入非法或正在保存时才禁用保存。
  保存失败保留草稿；版本冲突提示重新加载和核对，不能覆盖新配置。
- 试算区不再放第二个可编辑倍率框，直接使用上方当前草稿值，显示「按全局倍率 1.55× 试算」。
  修改草稿或用量使旧结果失效，但不阻塞保存。
- 移除试算区的订阅/余额切换，因为两者金额公式相同。保留 Standard、Priority、Flex 等
  真正影响单价的服务档位选择。
- 区分「恢复基础单价」和「恢复默认倍率」；恢复操作先作用于草稿，保存后才生效。
  不再让“清除单价覆盖”暗中修改倍率。
- 弹窗内容独立滚动，保存/取消固定在底部；窄屏字段纵向排列，按钮有足够触控面积。
  保存、试算、校验错误分别显示状态，不因试算中或试算失败无故禁用有效配置的保存。

### 分组配置页

- 「模型专属倍率」更名为「模型倍率覆盖」，明确表示覆盖全局。
- 使用紧凑规则行：模型 ID/末尾 `*` 前缀、覆盖倍率、删除操作。
  未设置规则的模型继承全局；添加规则时明确填写倍率，避免自动补 `1` 后意外覆盖全局。
- 精确模型可显示全局参考值；前缀规则会覆盖多个模型，不显示一个虚假的统一全局参考值。
- 提供可选的模型 ID 解析预览，显示最终值和来源：分组精确、分组前缀、全局或默认。
  预览复用后端解析器，界面不重复实现匹配算法。
- 删除规则的提示说明会继续匹配其他分组规则，再回退全局。
  不增加分组整体倍率、用户折扣到模型价格弹窗。

## 配置、API 与运行时

### 持久化和兼容

- 在现有 `settings` 表新增 `model_rate_multipliers` 配置键，保存精确模型到倍率的映射。
  不增加数据库表或 SQL 迁移；键缺失时视为空映射。
- 将倍率映射加入 `PricingService` 不可变配置、配置版本哈希、启动恢复及模型目录。
  只配置倍率的模型也应命中「已配置」筛选，并出现在列表中。
- 审查全部配置写入口（含通用设置中的模型映射更新）和分离试算副本。
  只改单价或映射时必须保留全局倍率；试算复制完整配置，不能漏复制倍率映射。
- 别名、单价覆盖、倍率及价格审计记录由同一次 `SetMultiple` 原子写入。
  数据库写入失败时，内存中的生效配置不变。
- `PUT /admin/settings/model-pricing` 增加 `global_model_rate`：
  字段缺失表示保留，`null` 表示删除该模型的全局配置，数值表示明确配置。
  必须区分缺失、`null`、`0` 和 `1`，防止旧界面或旧 API 调用清掉新配置。
- GET 返回保存值和实际默认值；历史记录增加倍率前后值。旧历史缺少该字段时标记未记录，
  不用当前配置推断旧倍率。
- 继续使用 `expected_version` 做并发保护，倍率修改也会使旧版本失效。
  单进程保存成功后立即作用于后续计费；多进程沿用当前定价配置的同步/重载要求，
  不声称一次本地内存更新能即时更新全部节点。

### 统一解析与收费

- 将分组规则查找调整为返回「是否命中、倍率、规则」，避免目前返回 `1` 导致无法区分
  未配置和明确配置 `1`。
- 增加唯一的最终模型倍率解析器，返回倍率、来源、命中规则和配置版本。
- 将全局倍率接入既有 `applyUserBillingFactors` 收费链路；覆盖 Claude、OpenAI HTTP/WS/WS v2、
  Gemini 长上下文，以及这些入口现有的图片/视频收费分支。逐一确认调用路径，避免漏接或重复相乘。
- 价格和全局倍率来自一致的配置快照；在并发修改配置时，不能把旧单价和新倍率拼在同一条收费记录中。
  用量记录写入本次实际使用的最终倍率，而不是事后查询当前设置。
- 复用现有 `usage_logs.model_rate_multiplier` 保存最终值；在可扩展的定价快照 JSON 中记录
  倍率来源/规则，管理员用量提示改为「有效模型倍率」。旧记录没有来源时显示未记录。
- Native Chat 独立按次收费继续遵循其现有合同，不把 Token 模型价格编辑入口用于修改冻结的按次价格。
  实现审查时明确标注这些独立入口，避免把支持范围扩大成未验证的计费承诺。

## 实施顺序

1. 实现配置模型、启动恢复、原子保存、版本及审计；补齐缺失/null/0/1 的兼容测试。
2. 实现统一解析器，并接入所有上述收费入口与记录快照。
3. 调整模型价格页、分组规则编辑器、用量来源提示、中英文文案及前端 API 类型。
4. 完成保存后的真实结算链路测试及 UI 验收，再构建不可变镜像。
5. 在隔离测试环境按其当前保留数据库版本的发布流程验收，记录镜像、备份和回滚版本。
   此方案本身不执行部署或修改线上倍率。

回滚记录要说明收费兼容性：旧镜像不读取新全局倍率配置，回退后会恢复旧收费规则。
如果已启用非 `1` 的全局倍率，应明确处理该收费行为变化，不能把“没有数据库迁移”
等同于“回退后价格完全一致”。优先使用兼容新配置的修复镜像，保留配置与历史账单。

## 必须通过的验收

主验收必须覆盖「保存 → 重新读取 → 新请求结算」，不能仅以试算正确作为完成依据：

1. 在隔离测试数据库、真实配置/用量仓储及本地 Mock 上游构成的测试中，把全局倍率保存为 `1.55`。
   不点击试算也能保存；重新打开和重新启动服务后仍读取 `1.55`。
2. 未命中分组覆盖时，新请求的记录倍率为 `1.55`；基础金额 `$0.10`、其他倍率为 `1` 时，
   订阅消耗或钱包扣费为 `$0.155`，Key 限额与订阅缓存金额一致。
3. 分组覆盖为 `2` 时扣 `$0.20`，不能扣 `$0.31`；覆盖为 `1` 时扣 `$0.10`；覆盖为 `0` 时用户金额为 `0`。
4. 删除覆盖后重新匹配分组前缀；没有其他分组命中才回退全局。
   删除全局且分组未命中后，回退默认 `1`。
5. 覆盖优先级在服务档位、长上下文、缓存分类以及 HTTP/WS 入口一致。
   按量、订阅的相同输入得到相同最终用户金额，上游账号成本保持既有口径。
6. 配置写入失败、旧版本编辑、旧请求遗漏字段、后台价格源刷新和并发保存不能丢失倍率配置。
7. 重复结算保持幂等；免费订阅请求不误扣钱包，缓存不重复累计。
8. UI 验收包含键盘操作、输入校验、保存失败保留草稿、移动端布局，以及旧试算失效但仍可保存。

测试使用合成凭据、本地 Mock 和专用测试模型/分组，不发送真实供应商模型请求，
不改写真实用户的历史用量或为了验收临时修改其价格。
