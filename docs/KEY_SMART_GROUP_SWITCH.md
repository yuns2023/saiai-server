## 用户行为

- 每个 Key 默认关闭智能切换，关闭时保持现有单分组行为。
- 开启后，用户勾选同服务下有权使用的分组，通过拖拽或上移/下移排序。
- 第一项优先级最高；每个新请求从第一项开始评估，没有永久的“当前分组”。
- 订阅触限、过期或分组无法承接请求时，按顺序选择下一项。
- 高优先级恢复后，新的独立请求自动回归；正在处理的请求不迁移。
- 勾选按量分组必须明确确认其价格及自动扣余额行为；提供可选的按量兜底预算。
- 用量详情展示实际分组、实际计费类型和本次兜底原因。

“同服务”第一版按 Key 原绑定分组的 platform 和兼容的入口协议确定，不跨
Claude/OpenAI/Google 平台，不自动替换请求模型。模型映射不得导致跨候选语义变化。
托管额度、图片/视频异步任务等特殊计费或状态协议需要单独验收后才可加入。

## 已确认的实现约束

基于规划时已获取的 Server main（c0b218a83）检查：

- `backend/internal/server/middleware/api_key_auth.go` 会在 handler 前检查绑定
  分组状态、订阅存在性和额度，并直接返回拒绝。仅在 handler 加 fallback
  无法覆盖订阅耗尽的主要场景。
- `backend/internal/service/api_key_service.go` 的 `GetAvailableGroups` 已提供
  活跃且用户可绑定的分组，订阅依赖有效订阅，普通分组依赖现有访问权限及等级。
  应复用权限语义，不另外创建绕过权限的候选列表。
- `backend/internal/handler/gateway_handler.go` 已有针对特定错误的管理员
  fallback。它与用户选择的有序策略不同，不能直接复用或串成第二条隐式链。
- `backend/internal/service/api_key_auth_cache_impl.go` 缓存 Key 和绑定分组快照；
  新策略必须纳入快照、版本兼容和失效机制，不得原地修改缓存对象。
- `backend/ent/schema/usage_log.go` 已有实际 `group_id`、`subscription_id`；
  应保留其语义，并补充路由来源和原因，避免按原绑定分组归账。
- OpenAI 有 `previous_response_id` 和 WebSocket 路径；有状态续接不能假定可跨账号迁移。

## 路由与失败分类

每次请求执行以下顺序：

1. 校验 Key、用户身份、IP、安全状态、Key 有效期、总预算、用户/Key 限速等全局限制。
2. 读取策略快照，解析本次模型和协议，建立请求级候选列表。
3. 对候选重新检查权限、服务/模型兼容、分组状态、订阅或余额及价格可用性。
4. 在候选分组内部执行既有账号选择、粘性、额度和并发规则。
5. 仅当该分组无法承接时前进到下一候选；每个候选最多访问一次，并共享请求总重试预算。
6. 固定本次有效分组、订阅、费率和策略版本，执行转发，按实际承接方记账。

| 原因 | 行为 |
| --- | --- |
| 订阅窗口额度耗尽、订阅过期 | 跳过，窗口恢复或续费后重新参与 |
| 分组停用、删除、授权被收回 | 不使用该组；其他已授权候选可继续，UI 标记原因 |
| 分组无可调度账号、账号全部冷却 | 组内调度结束后尝试下一候选 |
| 当前组不支持模型 | 仅跳过该组，不改模型；全局禁止模型则直接拒绝 |
| 当前按量候选余额不足 | 跳过付费候选；后续合法订阅仍可参与 |
| 用户/Key 禁用、过期、预算耗尽、安全限制 | 终止，不得换组绕过 |
| 请求错误、客户端取消、全局模型限制 | 终止 |
| 权限/计费依赖读取异常 | 返回服务错误，不伪装成额度不足而引发按量消费 |
| 上游明确拒绝且确认可重试 | 先按现有组内规则处理，再考虑下一组 |
| 超时且执行结果不明、响应已提交或已输出 | 不跨组重放 |

原绑定分组在关闭智能切换时保持现有语义；开启时它只确定服务归属和关闭后的
回退配置，不能因为该组过期/停用而在候选评估前阻断所有合法候选。
原分组被删除导致服务归属无法确定时停止并要求修正配置，不能猜测目标平台。

智能切换启用时只允许显式勾选的候选；现有管理员 fallback 不得转入未勾选组。
关闭时保留旧行为。此变化必须有兼容性回归测试。

## 恢复、粘性和有状态请求

- 额度恢复依据实际窗口/订阅状态，不为每个 Key 持久化一个当前活动分组。
- 已知上游限流重置时间沿用现有账号/模型冷却规则，不能扩大成全组停用。
- 临时故障采用有上限的短暂冷却；恢复尝试由真实新请求承担，不主动发送模型探测。
- 需要半开控制时使用跨进程租约，按故障实际作用域区分组、模型和协议，避免
  单一模型错误熔断整个分组。租约失败不能放过权限或计费检查。
- 普通完整上下文请求先选择分组，再在选定组内使用粘性。不能因低优先级粘性
  永久阻止恢复，也不能清除其他组已成功确认的粘性。
- WebSocket 已建立连接及依赖上游历史的续接请求保持原路由，无法续接时明确报错，
  不自动跨组重放。恢复回归适用于新连接和可独立执行的新请求。
- `/v1/usage`、bootstrap、模型列表和状态查询不能触发模型探测或付费兜底；
  其展示语义要独立验收，不能把某个动态分组冒充 Key 永久绑定。

## 数据与接口草案

建议 Key 策略字段：

```json
{
  "smart_switch_enabled": false,
  "smart_switch_group_ids": [],
  "smart_switch_payg_confirmed": false,
  "smart_switch_payg_budget_usd": null
}
```

- 有序 ID 数组是唯一优先级来源，不允许重复、空的启用列表或跨服务候选。
- 第一版候选数量上限建议为 10，避免配置导致过多调度工作。
- 使用现有 Key 创建/更新接口及 DTO；字段省略表示保留，不等于清空。
- 策略原子更新并带版本号；并发编辑检查版本，避免静默覆盖。
- 保存时检查权限，执行时再次检查；配置中已过期候选保留并标注不可用，续费可恢复。
- 返回候选 ID、名称、价格/倍率、订阅状态、可选性及原因，不返回账号或凭据。
  全部分组展示以现有可见性权限为边界，不泄露不可见分组。
- 先读取 canonical main 再分配迁移号，同步 Ent schema 和生成代码。

预算第一版采用每 Key 累计“智能切换使用按量产生的费用”，不随排序、关闭再开启
或策略重存清零。`null` 表示未设置，0 表示禁止按量；只统计该策略下实际按量费用。
UI 展示已用及剩余，允许提高上限，降低到已用以下立即阻止新的按量请求。
固定点金额运算、幂等结算和跨进程并发必须覆盖。

现有订阅是请求前检查、完成后记账，不能宣称严格防止单次请求越过限额。
新增兜底预算同样需要清楚标为请求准入阈值：已开始的并发请求最终费用可能超出。
若要求严格硬上限，则必须增加可靠的费用预留/释放/结算机制后才能如此宣传。

请求级路由记录至少包含：策略版本、原绑定分组、实际分组、候选排名、跳过原因。
用量日志记录最终实际分组/订阅；失败日志记录原因列表；两者均不得包含 Key 明文、
请求正文或上游凭据。扣费只执行一次，不能把候选检查记为一次消费。

## 实施拆分

### 1. 策略存储与管理界面

迁移、Ent、仓储、服务、DTO、鉴权快照和缓存失效；Key 编辑增加开关、勾选、排序、
按量确认和预算。已有 Key 默认关闭。后端路由验收前不开放可操作的生产入口。

主要入口：`backend/ent/schema/api_key.go`、`backend/internal/service/api_key_service.go`、
`backend/internal/handler/api_key_handler.go`、`frontend/src/api/keys.ts`、
`frontend/src/views/user/KeysView.vue`，必要时提取独立策略编辑组件。

### 2. 请求前选择与计费一致性

拆分全局鉴权和候选计费检查，增加共享候选选择器及请求级上下文。
先完成订阅触限 → 按量 → 窗口恢复的完整路径；所有已开放协议入口必须使用
一致的权限、预算和实际分组归账规则。Google 独立鉴权路径须显式覆盖或禁止配置，
不能仅修改 Claude 路径就宣称 Key 级功能完成。

### 3. 分组不可用兜底与恢复

接入现有组内调度失败结果、明确可重试错误分类、总尝试次数和时间预算；处理响应
提交边界、失败冷却、粘性与有状态续接。补充用量展示及可解释的错误信息。

### 4. 验收与交付

使用本地 mock 和可控时钟完成以下矩阵，再跑所需 CI。代码、数据库迁移、前端和
缓存格式作为一个功能批次交付。功能关闭不能撤销已产生的按量账单。
发布准备记录精确源码/CI/迁移及回滚约束，生产变更仍单独审批。

## 必须通过的验收

1. 订阅可用时，即使按量余额充足，也只扣订阅。
2. 订阅 5h/日/周/月额度触限后，同一 Key 使用下一合法候选，并按实际组价格结算。
3. 可控时钟推进至额度恢复或续费后，下一独立请求重新使用高优先级订阅。
4. 三个分组顺序正确，不重复尝试；全部不可用时返回有归因的错误且无虚假消费。
5. Key 预算/有效期/限速、用户禁用或安全限制不能通过切换绕过。
6. 授权撤销、等级降低、组停用及删除后立即生效，缓存失效与并发保存不产生越权。
7. 模型不匹配、无有效价格、不同平台均不能静默换模型或错误计费。
8. 某一账号 429 先走组内选择；全组无容量才跨组，模型限流不扩大到其他模型。
9. 响应已开始、上传失败/结果不明、客户端取消时不跨组重放；重试预算有界。
10. 同一请求幂等结算，按量阈值累计不被重存/切换开关重置；并发超额语义可见。
11. 订阅转按量清除旧订阅上下文，按量转订阅加载正确订阅；缓存 Key 对象保持不变。
12. 低优先级粘性不阻止新独立请求回归；有状态续接和 WebSocket 不发生历史丢失。
13. 智能切换关闭保持旧行为；开启不能通过旧 fallback 跳到未授权或未勾选分组。
14. 状态查询及初始化不发送模型请求；列表、日志、预算和 UI 均不泄露敏感内容。
15. UI 覆盖勾选、键盘排序、确认按量、保存失败及已选组失效；中英文文案一致。

测试串行执行，Go 使用 `GOMAXPROCS=2`、`-p 1`，覆盖选择器、鉴权、计费、handler
及缓存失效；前端执行相关组件测试和类型检查。不得使用用户真实 Token 发模型请求。
